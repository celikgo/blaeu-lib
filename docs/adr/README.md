# Architecture decision records

An ADR here records one decision that a later reader would otherwise have to reverse-engineer —
the constraint that forced it, what was chosen, **what was rejected and why**, and the costs
that came with it; the four-section template and the rule for when a change needs one are in
[CONTRIBUTING.md](../../CONTRIBUTING.md#when-a-change-needs-an-adr).

Decisions are amended rather than rewritten, so an ADR's header carries its own relations and
the last column below repeats them: read a superseded claim and the amendment is one link away.
